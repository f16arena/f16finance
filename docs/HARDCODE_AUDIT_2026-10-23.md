## 1. Ломает расчёт у любого нового клиента

- **Смены вне кодов arena/ramen/extra не попадают в ЗП** — `DEFAULT_COMPANY_CODES` фильтрует доходы (`lib/core/constants.ts:3`, `lib/domain/salary.ts:528,684`). У Castle коды CASTLE/SHAIQAS → ЗП операторов = 0.
- Те же коды в KPI, доходах, аналитике: `lib/kpiEngine.ts:3`, `app/api/admin/kpi-dashboard/route.ts:42`, `app/(main)/income/add/page.tsx:155,403`, `app/(main)/structure/page.tsx:146` (должность старшего зависит от `code==='ramen'`).
- Фейковый «ФП» и «фискализация: тестовый режим» на каждом чеке (`desktop/operator/src/lib/receipt-html.ts:109-111,263-264`) — юр. риск для клиента на ОУР.

## 2. Структура: точка → должности → люди

- Нет охвата роли (одна точка / несколько / вся орг-я): `resolveCompanyScope` даёт всё (`lib/server/organizations.ts:633-669`). «Управляющий двух точек из пяти» невозможен.
- Роли на точке — фиксированные три: operator / senior_operator / senior_cashier (check в `20260315_operator_company_assignments.sql:14`), бонусы — колонки `senior_*_bonus`.
- Роли орг-и — фиксированные owner/manager/marketer/other (check в `20260331_saas_foundation.sql:61`), кастомная должность сводится к `other` (`organizations.ts:97-103`).
- Два вида людей: operators и staff, склейка по Telegram/**имени** (`app/api/admin/hr/route.ts:203-232`), флаг `is_admin_staff`.
- Нет мастера новой точки: создание орг-и/компании — одна строка, без должностей, смен, кассы (`app/api/admin/organizations/route.ts:468-646`, `app/api/admin/companies/route.ts:87`).
- Точка = компания, режимы точки — фиксированный список (`point-devices/page.tsx:110`, `point-sales-core.ts:43-46`); по умолчанию `shift-report` молча выключает продажи.

## 3. Зарплата

- Период оператора — неделя пн–вс, закреплено в БД: `unique(operator_id, week_start)`, `check(week_end = week_start + 6)` (`20260320_weekly_salary_payments.sql:22-24`). Понедельник считается в ~12 местах, включая кассу, iOS, мобилку, копилот.
- Админ-состав — только две выплаты 1–15 / 16–конец, половина оклада = `salary/2` (`lib/domain/staff-salary-slot.ts:51-61,184-202`; `app/api/admin/staff-salary/route.ts:1109-1135`). Выплата за октябрь 5 ноября попадёт в «первую половину ноября».
- Подписи «выплата 1-го / 15-го» противоречат логике 1–15 / 16–конец.
- Формула: только смена + пороги выручки; нет %-от-выручки, почасовой; смены только day/night; бонус стажа ≤15% в коде и в check; «Доп. выход» распознаётся по тексту комментария.
- Нет лимита аванса и лимита удержания долга за период.

Нужно: `pay_schedule` орг-и/должности (daily / weekly(день) / biweekly(якорь) / semimonthly(день) / monthly(день выплаты, смещение периода)) + общая таблица периодов вместо `+6`; модель оплаты по должности (смена / час / % / оклад / смешанная).

## 4. Финансы и отчёты

- Способы оплаты — фиксированные колонки `cash/kaspi/card/online_amount` (~60 файлов), POS — только cash/kaspi (check cash/kaspi/mixed). Нужен справочник `payment_methods` орг-и + строки оплат.
- Смены day 08–20 / night 20–08, ночь по дате начала, `kaspi_before_midnight` (`lib/core/kz-shift.ts`, check `shift in ('day','night')`). Нужны шаблоны смен точки + `business_day_cutoff`.
- Часовой пояс UTC+5 в ~57 файлах (`KZ_OFFSET`, `kzTodayISO`, `Asia/Almaty`), а в админке по умолчанию `Asia/Qyzylorda`.
- Налог — ИП упрощёнка 910 (`lib/domain/tax.ts`), копилот считает 3%, страница — 2%.
- «F16 Extra» исключается по имени/коду (~30 файлов) → `companies.exclude_from_totals`.
- Категории расходов по тексту: `'Зарплата'`, `ilike '%списан%'`, список F16 в ИИ-парсере чеков.
- Эквайринг в прибыльности — только Kaspi (qr/gold/red/kredit).
- Валюта ₸ (669 мест) и ru-RU (581) без общего форматтера.

## 5. Магазин, склад, касса, арена

- Склад только «склад → витрина» с обязательным согласованием; продажа только с витрины.
- Приёмка требует файл накладной и чек оплаты, категорию себестоимости.
- Списание — авто-расход, категория по имени, всегда в kaspi, отключить нельзя.
- Поля сменного отчёта F16: coins, kaspi_pos, kaspi_online, debts, wipon, «Senet».
- Лояльность по точке и в тенге (`points_per_100_tenge`).
- Арена завязана на SENET (выключается флагом `arena_enabled` — это ок).
- `companies.industry` влияет только на базу знаний, не на поведение кассы/склада.

## 6. Уведомления, кроны, ИИ, бренд

- Время рассылок зашито в UTC под Алматы (vercel.json → `/etc/cron.d/orda`); нужно ежечасно + «по локальному времени орг-и».
- Напоминания о сменах 09:00/21:00 фиксированы.
- ИИ-промпты: «сеть игровых клубов в Казахстане, владелец Олжас», «Азамат», зоны `['PC','arena','ramen','extra']`.
- Праздники — только КЗ, текст на казахском.
- Бренд/ссылки: «Orda Control», github.com/f16arena/f16finance в кассе/киоске, `f16.*` ключи localStorage, slug `f16` по умолчанию, `padash00@gmail.com` фолбэком для заявок.

## Порядок работ (предложение)

1. **Утечки L1–L6** — маленькие правки, безопасность первого клиента.
2. **Ломающее расчёт** — убрать фильтр `DEFAULT_COMPANY_CODES`, правила ЗП по `company_id`, ФП на чеке только при реальной фискализации.
3. **Слой настроек организации** — timezone, валюта, начало недели, получатели уведомлений; читать его везде вместо констант.
4. **График и модель оплаты** (зарплата, раздел 3) — F16 переносится настройками «неделя» и «1–15/16–конец» без изменения сумм.
5. **Охват должностей + свои должности точки** (раздел 2).
6. **Способы оплаты справочником** и **шаблоны смен** — самая широкая миграция (данные, касса, iOS, отчёты).
7. **Единый сотрудник** вместо operators/staff.
8. **Мастер новой точки** поверх 3–7.
